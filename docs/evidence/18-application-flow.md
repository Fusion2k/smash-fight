## Exact remaining Windows human procedure (H1/H2/H5)

1. Unpack the complete Windows archive and launch `smash-fight.exe`. Record Windows version, output/resolution, renderer, build/source, both controller models and USB/Bluetooth modes.
2. Two people press Start on separate gamepads, independently select Zip/Bramble and ready with bottom face/Start. Play full three-stock matches, use a same-character pair, rematch twice, then either player returns to selection with top face and starts again. Confirm markers, damage, stocks and result ownership/readability. A developer draw is reproducible with `smash-fight.exe -- --verify-quit --capture-phase=results`; this bounded diagnostic intentionally ends after capture/startup verification.
3. Verify analog movement, up/down attack directions, bottom-face jump, left-face attack, top-face recovery, and Start pause from either pad. Fresh down alone drops through a one-way platform; holding down does not repeatedly drop. Verify descending fast-fall and no stick-up jump.
4. Disconnect during play, initial countdown and resume countdown. Confirm all gameplay clocks/state freeze. Reconnect and press Start explicitly, or use an unassigned replacement. Confirm connected ownership cannot be stolen, identity/damage remain, there is no automatic resume, a fresh three-second resume occurs, held actions do not leak and interrupted initial countdown resumes its remaining phase.
5. Run Developer Test from the button or `smash-fight.exe -- --developer-test`: WASD, Space, J, K and Escape. Run normal keyboard plus one pad through Join keyboard player. Check controls across pause, results, reselection and repeated restarts. For the authoring/tuning portion, use a source checkout with `tools/dev.ps1 test` and `tools/dev.ps1 editor`; exported PCK content does not read edits from the repository and exported-game modding is deferred. Save a source JSON damage/physics change and restart Developer Test to observe it; use the editor to save one geometry/timing change and repeat without adding JSON geometry. Test invalid JSON, its diagnostic, correction and retry. Follow the full H5 developer/tuning acceptance in `docs/first-playable-acceptance.md` and record observed defects; do not infer it from these automated checks.
